## 1. 系统总览

```
index.html（唯一入口页）
│
├─ [ 标注系统 ]  正式标注生产          ├─ [ 教学系统 ]  学生练习平台
│         ↓                                    ↓
│   标注系统登录页                          教学系统登录页
│   邮箱（手机号可选）+ 密码
│         ↓
│   团体层
│   ├ 没有团体 → [ 创建团体 ]   [ 加入团体 · 输入身份码 ]
│   └ 已有团体 → 下拉选择进入哪个团体 + [ 新建 ] [ 加入 ]
│         ↓
│   工作界面（针对当前团体，可随时切团）
```

**两个系统分开管**：各自一套账号、一套登录页、一套外壳与导航、一套浏览器存储。底层引擎（形式化表达解析、图示渲染、标注结果的数据结构）共用一份。

## 2. 标注系统

### 2.1 入口与账号

- 账号=一个人。登录标识以**邮箱**为主，手机号可选。
- **自助注册**：登录页提供「注册申请」入口，填写姓名、邮箱、单位后提交，等待审核。
- **审核方是开发维护方**，属于系统之外的角色。原型中不为其制作界面，只呈现「申请已提交，等待审核」状态。
- 账号本身**不含任何业务权限**——权限全部来自团体内的成员身份。

### 2.2 团体

- 团体是标注工作的单位，也是数据的边界。
- **创建**：任何登录用户都可以创建团体，创建者默认成为该团体的**最高管理**。
- **加入**：输入团体**身份码**提交申请 → 由该团体的管理员审核通过。
  - 身份码为每个团体一个固定码，最高管理可重置。
- **切换**：登录后进入团体层，已有团体的用户用下拉选择进入哪一个；工作界面内常驻「团体管理」，可随时切换、新建、加入。
- **数据隔离**：文书、任务、标注结果全部挂在团体上，团体之间互相不可见。

### 2.3 团内身份

一个人可以拥有多个身份，角色**逐团体**成立——在 A 团是管理员，在 B 团可能只是标注员。

| 身份 | 说明 |
|---|---|
| **最高管理** | 创建团体者默认获得。 |
| **管理员** | 由最高管理指定，可以多人，权限与最高管理基本相同。 |
| **标注员** | 由管理员指定。 |
| **裁定员** | 由管理员指定。 |

- 身份由**管理员指定**，本人不能自行选择或退出。
- 被指定身份后即自动获得对应功能；被管理员推送的任务会自动出现在本人的列表里。
- 管理员可以**给自己也指定**标注员 / 裁定员身份，从而进入对应的区干活。
- **最高管理比普通管理员多出的权力**：转交管理权限、解散团体、移除管理员。
- 普通管理员可以移除标注员 / 裁定员，但不能动其他管理员。

**待定项**（不影响原型开发）：普通管理员能否罢免另一个管理员。

### 2.4 侧边栏

侧边栏按「我在当前团体拥有哪些身份」动态渲染，切团后随之变化。

```
┌─ 团体：法律论证实验室  ▾ ──────────┐   ← 切换团体 / 新建团体 / 加入团体
│                                   │
│  概览                              │   所有人（按身份显示不同待办块）
│                                   │
│  管理区                            │   ← 有 最高管理 / 管理员 身份才出现
│    文书与语料                       │
│    标签体系                         │
│    任务创建与分配                    │
│    成员与身份                       │
│    结果输出                         │
│                                   │
│  标注区                            │   ← 有 标注员 身份才出现
│    我的任务                         │
│                                   │
│  裁定区                            │   ← 有 裁定员 身份才出现
│    待裁定                           │
│    已定稿                           │
└───────────────────────────────────┘
```

**标注工作台不占侧边栏条目**，它是从「我的任务」点进去的**下钻页**（全屏，带返回）。

### 2.5 任务模型

任务是一个**管理单位**（一个「筐」），文章数量不限——可以只装 1 篇，也可以装一批关联性强、需要同几个人一起做的文章。

```
任务「劳务合同纠纷标注任务 A」
  标注员   陈璐 · 李维 · 张倩
  裁定员   王敏
  文书     余某诉徐某劳务合同纠纷        ← 指名给 陈璐、李维
           中原公司诉陶德华居间合同      ← 指名给 张倩
  统一 ddl  2026-10-20
  单篇 ddl  可覆盖统一值
```

- **细分指派**：管理员指定谁标哪几篇。**没有指定的，就没有任务**。
- 指派可以在任务创建后变更。
- 裁定员按任务指定（不是公共池）。
- 每个「文章 × 人」的分配是一条独立记录，带自己的状态与截止日期。
- 「阶段 01 创建 / 02 标注 / 03 裁定 / 04 输出」仍挂在**任务**上。

> **可选、本期不做**：批量指定、按人筛选的辅助按钮。

### 2.6 页面清单

| 区 | 页面 | 职责 |
|---|---|---|
| — | 概览 | 按身份显示待办与指标 |
| 管理 | 文书与语料 | 上传、查看、删改本团文书；按规则提取裁判理由，人工校正 |
| 管理 | 标签体系 | 查阅要素类型与关系类型；任务开始后锁定 |
| 管理 | 任务创建与分配 | 建任务、选文书、细分指派、定 ddl |
| 管理 | 成员与身份 | 审核加入申请、指定/变更身份、移除成员、重置身份码 |
| 管理 | 结果输出 | 导出配置 / 导出记录 / 结果查看 |
| 标注 | 我的任务 | 被指派给我的任务 → 下钻进入标注工作台 |
| 裁定 | 待裁定 | 指派给我、且标注已提交齐的任务 → 多版本并排比对与裁定 |
| 裁定 | 已定稿 | 定稿记录 |

**从标注系统移出**：原「标准样例与学生标注」页归教学系统。

## 3. 教学系统

结构上是标注系统的轻量镜像（团体→班级，管理员→老师），但业务简单得多。

### 3.1 入口与账号

- 与标注系统同样的模式：本系统自己的登录页、自己的一套账号（老师 / 学生）。
- 登录后进入班级层：没有班级则「创建班级 / 加入班级」，已有班级则下拉选择。
- 加入班级：**输入班级码即入，不审核**（教学场景无需审核）。

### 3.2 班级

- 一个班级只有**老师**和**学生**两种身份，目前不设其他角色。
- 一个老师可以有多个班级，一个学生也可以在多个班级。
- 班级内常驻「班级管理」，可切换、新建、加入。

### 3.3 侧边栏

**老师**

```
┌─ 班级：法学2023级2班  ▾ ─────────┐
│  概览                            │
│  班级管理                         │
│    文档库        上传待标注文档    │
│    标准答案      给文档标出答案（复用标注界面）
│    练习          发一次练习 = 选文档 + ddl +（可选）到点自动发布答案
│    成员          班级码、学生名单
│    统计          选一次练习 → 完成情况 / 平均相似率 / 排行
└─────────────────────────────────┘
```

**学生**

```
┌─ 班级：法学2023级2班  ▾ ─────────┐
│  概览                            │
│  我的练习       老师发过的练习，带 ddl
│    └ 点进去 → 逐篇标、逐篇交
│  我的成绩       自己做过的练习的相似率
└─────────────────────────────────┘
```

### 3.4 练习模型

- **练习**是发放单位：老师选一批文档 + 定一个 ddl，全班做同一套，**不指派到人**。
- 老师上传的待标注文档全部在班级文档库里，学生可见。
- **标准答案**由老师用**同一套标注界面**标出，存放于文档之下。
- 老师可以设定 ddl、提前手动结束练习、修改练习配置（ddl、文档）。

### 3.5 标注与提交

- 学生做的是**完整标注**：命题 + 标签 + 关系，使用与标注系统**同一套三栏工作台**（原文 / 命题与标签 / 论证图示），一样能拖动图元建立 S / A / M / J / I、手动输入形式化表达、生成图示。
- **逐篇提交，可以重复提交**。第一次提交即视为完成。
- **查看答案的条件**：该篇**我已提交** **且** 老师**已发布**答案。老师可以设为 ddl 到点**自动发布**。

### 3.6 相似率与统计

- **相似率**只有一个指标，衡量学生结果与标准答案的重合度，**覆盖命题、标签、关系**。
- 具体核算与定义由后端实现；原型阶段在前端用一个简单重合度顶替，界面只呈现数值。
- **老师侧统计**（按练习）：
  - 完成人数 / 总人数
  - 平均相似率
  - 已完成的名单、未完成的名单
  - 学生相似率排行

### 3.7 页面清单

| 身份 | 页面 | 职责 |
|---|---|---|
| 老师 | 文档库 | 上传待标注文档 |
| 老师 | 标准答案 | 为文档标出标准答案 |
| 老师 | 练习 | 发布练习、设定 ddl、发布/自动发布答案、提前结束 |
| 老师 | 成员 | 班级码、学生名单 |
| 老师 | 统计 | 按练习查看完成情况、平均相似率、排行 |
| 学生 | 我的练习 | 老师发过的练习列表 → 逐篇进入工作台 |
| 学生 | 我的成绩 | 自己做过的练习的相似率 |

## 5. 数据模型

两个系统各自一份 state，分 key 存于浏览器。

### 标注系统

```
accounts[]                 平台账号：姓名、邮箱、手机号、单位。不含业务权限
registrationRequests[]     注册申请（开发维护方审核）

teams[]                    团体
  ├ name, inviteCode
  ├ ownerId                          最高管理
  ├ members[] { accountId, roles:[admin|annotator|arbiter] }
  └ joinRequests[]                   身份码申请 → 管理员审核

documents[]                { teamId, title, short, kind, reason, meta, uploadedBy }
tasks[]                    { teamId, name, stage, deadline, createdBy,
                             items:[ { docId, annotators[], arbiters[], deadline } ] }
annotations[]              { taskId, docId, accountId, elements[], relations[],
                             status, submittedAt }
finals[]  exports[]  log[]
```

### 教学系统

```
accounts[]                 另一套账号（老师 / 学生）
classes[]                  班级
  ├ name, classCode
  └ members[] { accountId, role: teacher|student }

documents[]                { classId, title, reason, meta,
                             answer:{ elements[], relations[] } }
exercises[]                { classId, name, docIds[], deadline, autoPublish, published }
submissions[]              { exerciseId, docId, accountId, elements[], relations[],
                             status, submittedAt, similarity }
```

## 6. 共用部分

以下两份数据结构在两个系统中**完全一致**，因此三栏工作台、图示引擎、相似度计算可以两边共用：

```
命题  { seq, code, sub, text, start, end }
关系  { id, tree, label }          tree 为术语树 { t:'S', c:[ … ] }
```

共用引擎：形式化表达的解析 / 打印 / 校验 / 命题角色推导、关系树 → 分层图、SVG 图示渲染、DOM 与浮层助手。

## 7. 继承与不变的部分

以下继续依据《指南 v1.1》执行，本次变更不动：

- 标注对象为裁判理由部分；颗粒度以句号第一次切割、过渡语词并入其后第一个要素（§2.3）
- 要素类型：命题层 GM / SM / GF / SF，非命题层 IS / Non；GM 子类为 GM-L / GM-I / GM-U / GM-M / GM-O；**合同及合同解释为 SM-C，挂在 SM 下**
- 关系五类：S 支持 / A 反对 / J 组合 / M 匹配 / I 同一
- 图示规范（§6）：命题节点为矩形且不携带类型信息，关系节点为圆形，实心● / 空心○ / ⊕ / 框内「/」
- 嵌套结构六种（§5.3），自内而外逐层构造
- 命题角色（前提 / 子结论 / 结论）**不作为独立标注项**，由关系结构自动推导
- 冲突以指南（PDF）为准

## 8. 视觉与文案基调

- **简约高级**。有设计感，但不花哨、不炫技。信息密度服务于阅读，不服务于装饰。
- **文案大幅瘦身**。说明性、铺垫性、重复性的文字一律删除；界面上只留操作与数据本身。删除不影响理解的注释文字。
- 已有的纸墨配色与排版基因保留：文书正文用仿宋，界面用黑体，形式化表达用等宽。朱色仅用于「裁定 / 定稿 / 不可回退」语境。
- 不新增插画、渐变、阴影堆叠等装饰性元素。

## 9. 原型边界

原型为**纯前端**，无后端、无数据库、无构建步骤，`file://` 双击即可打开。

| 项 | 原型做法 |
|---|---|
| 数据存储 | 浏览器 localStorage；不可用时退化为内存态，界面照常可用 |
| 文件解析 | 不解析 PDF / Word 二进制。真实读取 `.txt`；拖入 PDF/Word 时载入内置语料作等价替代，并在界面标明 |
| 表格导出 | 导出 `.csv`（带 BOM，Excel 可直接打开），不生成 `.xlsx` |
| 位图导出 | SVG 经 canvas 转 PNG / JPG；浏览器限制时回退为 SVG 下载 |
| 注册审核 | 只呈现「等待审核」状态，无审核界面 |
| 相似率 | 前端以简单重合度顶替，真实算法由后端实现 |
| 图示布局 | 自顶向下分层，拓扑与图元与指南一致，坐标不逐像素还原 |
